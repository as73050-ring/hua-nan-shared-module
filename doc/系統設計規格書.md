# 壹、系統概述

## 一、系統目的

提供華南銀行外撥語音（IVR）流程的設定管理介面，讓業務人員可自行新增、編輯、匯入匯出外撥語音流程，無需工程師介入。

## 二、三種樣板類型

| 樣板類型 | 適用場景 | Part 2 差異 |
|----------|----------|-------------|
| 滿意度類 | 問卷調查（理財滿意度等） | 問卷套用區（問卷代碼對應題目預覽） |
| 客戶意願確認轉真人服務類 | 確認客戶意願後決定後續動作 | 主流程區（多區塊，每區塊帶回應設定） |
| 業務資訊通知類 | 單向通知訊息後結束 | 通知內容區（單一台詞播放後結束） |

## 三、流程結構

三種樣板類型目前共用以下結構：

```
基本資訊（流程編號、名稱、樣板類型、啟用狀態、Skills、問卷代碼）
├── 共用回應處理規則（此流程共用，6 條規則）
├── PART 1 開場白區（多區塊，每區塊 1 台詞 + 回應設定）
└── PART 2 （依樣板類型不同）
    ├── 滿意度類 → 問卷套用區
    ├── 客戶意願確認轉真人服務類 → 主流程區（多區塊）
    └── 業務資訊通知類 → 通知內容區（單一台詞）
```

# 貳、列表頁（流程管理）

## 一、畫面示意

![列表頁](https://github.com/as73050-ring/hua-nan-shared-module/blob/dev3/doc/screenshots/01-list-page.png?raw=true)

## 二、功能描述

外撥語音流程的總覽頁面，顯示所有已建立的流程清單，提供查詢、新增、匯入匯出、編輯、刪除等操作。

## 三、查詢條件

列表頁上方為查詢條件區塊（`.query-panel`），欄位如下：

| 欄位 | 元素 ID | 型別 | 說明 |
|------|---------|------|------|
| ChatWeb主題ID | `q-topic` | select | 目前僅一個選項：「202260915144539497／華南外撥語音」 |
| 樣板類型 | `q-type` | select | 選項：請選擇／滿意度類／客戶意願確認轉真人服務類／業務資訊通知類；等於流程的 `type` 欄位 |
| 流程編號 | `q-flowno` | text | 依輸入文字比對流程編號（不分大小寫、部分比對） |
| 狀態 | `q-status` | select | 選項：請選擇／啟用（`on`）／停用（`off`）；比對流程的 `enabled` 欄位 |

查詢按鈕列（`.query-actions`）：

| 按鈕 | 元素 ID | 行為 |
|------|---------|------|
| 重填 | `btn-query-reset` | 清空「流程編號」「樣板類型」「狀態」三個查詢欄位後重新查詢（ChatWeb主題ID 欄位不受影響） |
| 查詢 | `btn-query` | 依目前「流程編號」「樣板類型」「狀態」三個欄位條件重新渲染列表 |
| 匯入流程 | `btn-import-flow` | 開啟檔案選取器 |
| ＋ 新增流程 | `btn-new-flow` | 進入空白表單頁（新增模式） |

> 備註：原本以關鍵字模糊比對「流程編號」及「業務流程名稱」的搜尋框（`#search-input` + `#btn-search`），程式碼與比對邏輯仍保留，但其外層容器 `.list-toolbar` 目前以 `style="display:none"` 隱藏，畫面上不會顯示，暫未對外開放使用。

## 四、查詢結果欄位

| 欄位名稱 | 對應資料欄位 | 說明 |
|----------|-------------|------|
| 流程編號 | `no` | 唯一識別碼，與 IVR 活動代碼對應 |
| 業務流程名稱 | `name` | 流程中文名稱 |
| 樣板類型 | `type` | 三種之一 |
| 狀態 | `enabled` | 「啟用」或「停用」 |
| 操作 | - | 編輯 / 匯出 / 刪除 按鈕 |

查無符合條件的流程時，表格顯示「查無符合條件的流程」。

## 五、操作按鈕

| 按鈕 | 功能 | 備註 |
|------|------|------|
| 查詢 | 依「流程編號 / 樣板類型 / 狀態」篩選列表 | 見「三、查詢條件」 |
| 重填 | 清空查詢欄位並重新查詢 | 見「三、查詢條件」 |
| ＋ 新增流程 | 進入空白表單頁（新增模式） | 流程編號由使用者輸入 |
| 匯入流程 | 開啟檔案選取器，讀取 JSON 檔案 | 支援多檔、陣列格式；編號重複時覆蓋 |
| 匯出全部 | 下載所有流程為 `all_flows.json` | JSON 陣列格式；**僅在查詢結果表格有資料時才顯示此按鈕**，查無資料時隱藏 |
| 編輯 | 進入該流程的表單頁（編輯模式） | 帶入已儲存資料 |
| 匯出 | 下載單筆流程為 `{流程編號}.json` | - |
| 刪除 | 確認後移除該流程 | 彈出 confirm 對話框 |

# 參、表單頁（樣板設定）－基本資訊

## 一、畫面示意

![基本資訊](https://github.com/as73050-ring/hua-nan-shared-module/blob/dev3/doc/screenshots/02-form-basic.png?raw=true)

## 二、新增 vs 編輯模式差異

| 項目 | 新增模式 | 編輯模式 |
|------|----------|----------|
| 流程編號 | 可輸入（必填）| 唯讀顯示（灰底）|
| 業務流程名稱 | 空白 | 帶入已儲存值 |
| 樣板類型 | 需選擇 | 帶入已儲存值（可切換，會重載下方區段）|
| 是否啟用 | 預設「啟用」| 帶入已儲存值 |
| 轉真人 Skills | 空白 | 帶入已儲存值 |
| 問卷代碼 | 依流程編號自動比對 | 依流程編號自動比對 |

## 三、欄位說明

| 欄位名稱 | 對應參數 | 型別 | 必填 | 檢核方式 | 錯誤訊息 | 備註 |
|----------|----------|------|------|----------|----------|------|
| 流程編號 | `no` | text | Y | 不可為空；新增時檢查不可重複 | 「請輸入流程編號」／「流程編號「XXX」已存在，請輸入不同編號」 | 新增後不可異動，與 IVR 活動代碼串接 |
| 業務流程名稱 | `name` | text | Y | 不可為空 | 「請輸入業務流程名稱」 | - |
| 樣板類型 | `type` | select | Y | 不可為空 | 「請選擇樣板類型」 | 切換後 Part 1/2 依樣板結構重載 |
| 是否啟用 | `enabled` | radio | Y | 必有選擇（預設啟用） | - | - |
| 轉真人 Skills | `skill` | text | Y | 即時過濾非數字字元（僅接受數字），不可為空 | 「請輸入轉真人Skills代碼」 | 輸入框，輸入非數字直接不顯示 |
| 問卷代碼 | `surveyCode` | text(readonly) | Y(滿意度類) | 依流程編號自動比對，無對應時報錯 | 「流程編號未對應啟用的問卷代碼」 | 僅滿意度類顯示（`#fld-survey-code`） |

## 四、轉真人 Skills 即時過濾邏輯

```
欄位型態：<input type="text" id="transfer-skill" inputmode="numeric">
即時檢核：每次 input 事件觸發時，將 value 中的非數字字元全部移除
  this.value = this.value.replace(/\D/g, '')
效果：使用者輸入英文或符號時完全不顯示，僅數字可輸入
儲存檢核：不可為空（submit 時檢查）
不限字數、不限特定代碼值
```

## 五、問卷代碼自動比對邏輯

```
觸發時機：流程編號輸入 (input) 或失焦 (blur) 時
比對邏輯：
  1. 取得目前輸入的流程編號值
  2. 從 surveys 資料中尋找 flow_no === 流程編號 且 enabled === true 的問卷
  3. 若找到 → 顯示問卷代碼值（如 Q001），清除錯誤樣式
  4. 若找不到 → 清空問卷代碼欄位，標示紅框+紅字錯誤訊息
資料來源：data/surveys.csv（欄位：code, name, flow_no, enabled）
```

## 六、樣板切換行為

- 選擇樣板類型後，`#dyn` 區域整體重新渲染
- **不覆蓋**流程編號與業務流程名稱（保留使用者已輸入值）
- 清除問卷代碼欄位的錯誤狀態（避免跨表單殘留）
- 重新觸發問卷代碼比對（滿意度類時）

# 肆、共用回應處理規則

## 一、畫面示意

![共用回應處理規則](https://github.com/as73050-ring/hua-nan-shared-module/blob/dev3/doc/screenshots/04-shared-rules.png?raw=true)

## 二、功能描述

每個流程共用的 6 條回應處理規則，定義當 IVR 辨識到特定客戶意圖時的固定處理方式。各 Part 的區塊可透過 checkbox 勾選「套用哪些規則」。

## 三、規則明細

| 規則名稱 | 處理方式 | 可設定項目 | 訪談結果（自動帶入） | 對應參數 key |
|----------|----------|------------|---------------------|-------------|
| 閒置 | 達標準後：再聽一次；達次數後：結束通話 | 台詞（1 個） | 本人 / 閒置 / 閒置 | `閒置` |
| 抱怨負面情緒 | 轉真人(NV05) | 台詞（1 個） | 本人 / 轉真人(敏感詞) / 轉真人(敏感詞) | `抱怨負面情緒` |
| 轉真人 | 轉真人(NV01) | 台詞（1 個） | 本人 / 轉真人 / 轉真人 | `轉真人` |
| 結束 | 結束通話 | 台詞（1 個） | 本人 / 本人接聽 / 無意願接受訪談 | `結束` |
| 再聯絡 | 再聯絡流程 | 台詞（4 個，見下表） | 本人 / 本人接聽 / 忙碌中，再聯絡 | `再聯絡` |
| 掛斷 | 結束通話（不需台詞） | 無 | 滿意度類：本人 / 本人接聽 / 未完成問卷；其餘樣板：非本人 / 客戶自行掛斷 / 客戶自行掛斷 | `掛斷` |

> 備註：「聽不懂」並非全域共用規則，而是各回應列可選的客戶回應意圖之一（`data/intents.csv`：是(意圖)／否(意圖)／聽不懂），選取後預設連動為「轉真人」＋轉真人原因 NV00（`聽不懂轉真人`）。

## 四、再聯絡子流程台詞

| 順序 | 台詞欄位 | 對應參數 | 說明 |
|------|----------|----------|------|
| 1 | 詢問可再聯絡日期 | `sr-cb1` | 詢問客戶方便的日期 |
| 2 | 確認聯絡時段 | `sr-cb2` | 確認上午/下午/晚上 |
| 3 | 覆述辨識結果 | `sr-cb3` | 覆述日期時段供確認 |
| 4 | 結束台詞 | `sr-cb4` | 確認後結束通話 |

> 備註：覆述辨識結果時，若用戶按鍵回覆 2（錯誤），流程回到步驟 1「詢問可再聯絡日期」重新開始。

## 五、區塊套用規則

每個區塊（Part 1/Part 2 的 block）底部有「套用共用判斷」checkbox 群組，勾選的規則會在該區塊的語音互動中生效。

| 項目 | 說明 |
|------|------|
| UI 元素 | 6 個 checkbox，標籤為各規則名稱（資料來源：`data/checks.csv`） |
| 資料儲存 | `applyRules: string[]`（僅存有勾選的 key 值） |
| 預設值 | 依樣板種子資料定義 |

## 六、收合/展開

- 點擊標題列可收合或展開整個共用規則區段
- 收合狀態下顯示「展開 ▼」，展開時顯示「收起 ▲」

# 伍、PART 1 開場白區

## 一、畫面示意

![PART 1 開場白區](https://github.com/as73050-ring/hua-nan-shared-module/blob/dev3/doc/screenshots/05-part1-opening.png?raw=true)

## 二、功能描述

流程開始後第一段語音互動。每個區塊包含一句台詞和一組回應設定，可新增多個區塊。

## 三、區塊結構

| 元素 | 說明 | 限制 |
|------|------|------|
| 區塊名稱 | 可編輯文字，用於「前往指定區塊」目標選單 | 不可為空 |
| 台詞 | 下拉選擇（來源：台詞池） | 每區塊最多 1 句台詞 |

# 柒、回應設定（通用）

## 一、功能描述

定義「播放台詞後，依客戶回應決定下一步」的設定。每個回應列由「意圖」+「動作」+「附加欄位」組成。

## 二、欄位組成

| 欄位 | 對應參數 | 型別 | 說明 |
|------|----------|------|------|
| 客戶回應（意圖） | `intent` | select | 選項：「是(意圖)」「否(意圖)」「聽不懂」（`data/intents.csv`） |
| 處理動作 | `action` | select | 依樣板類型不同（見「三、動作選項」） |
| 轉真人原因 | `reason` | select | 動作為「轉真人」時顯示 |
| 台詞 | `script` | select(searchable) | 動作為轉真人/結束通話/轉inbound 等時顯示 |
| 目標區塊 | `gotoBlock` | select | 動作為「前往指定區塊」時顯示 |
| 轉inbound帶入語句 | `inboundText` | text | 動作為「轉inbound」時顯示，預設帶入業務流程名稱 |
| 再聯絡台詞組 | `callback` | 4 x select | 動作為「再聯絡」時顯示（同共用規則的 4 步驟） |
| 通知欄位 | `notify` | 面板 | 動作為「訊息通知」時顯示 |
| 訪談結果 | `interview` | 3 x select | 動作涉及結案時顯示（接觸/類型/結果 三層聯動） |

## 三、動作選項（依樣板類型）

回應列的「處理動作」下拉選單資料來源為 `data/actions.csv`（依 `template` 欄位分組）；三種樣板類型目前實際可選動作如下：

| 動作 | 滿意度類 | 客戶意願確認 | 業務資訊通知 |
|------|----------|-------------|-------------|
| 進入問卷（主流程） | V | - | - |
| 播放通知內容（主流程） | - | - | V |
| 進入主流程區 | - | V | - |
| 前往指定區塊 | - | V | - |
| 再聽一次（重複本區塊） | V | V | V |
| 轉真人 | V | V | V |
| 轉inbound | V | V | V |
| 訊息通知 | V | V | V |
| 再聯絡 | V | V | V |
| 結束通話（送出以下結束台詞） | V | V | V |

> 備註：程式碼中另保留「留電」動作的顯示/隱藏連動邏輯（如訪談結果面板的顯示條件），且 JS 內建的種子資料（`TEMPLATES.*.actions`）與 fallback 動作清單仍列有「留電」，但目前 `data/actions.csv` 三種樣板的動作清單皆未包含「留電」，故此選項目前**不會**出現在實際下拉選單中，僅在還原含有此動作值的舊資料時才會顯示對應面板。
>
> 「訊息通知」合併原本 SMS/EMAIL/LINE/APP推播 四個選項，實際參數設定於參數管理頁「訊息通知」分頁維護（見玖、五）。

## 四、動作切換連動邏輯

```
當使用者切換「處理動作」時（syncActionFields）：
  - 轉真人 → 顯示：轉真人原因 + 台詞 + 訪談結果
  - 結束通話 → 顯示：台詞 + 訪談結果
  - 轉inbound → 顯示：帶入語句 + 台詞 + 訪談結果
    並顯示補充說明：若流程開關未開啟時則轉真人，轉真人原因、台詞、訪談結果同共用回應處理
  - 前往指定區塊 → 顯示：目標區塊下拉
  - 再聯絡 → 顯示：4 個台詞欄位 + 訪談結果
  - 訊息通知 → 顯示：通知欄位面板（見「六、通知面板欄位」）+ 訪談結果
  - 其餘 → 隱藏所有附加欄位
```

## 五、訪談結果三層聯動

```
資料來源：data/interview.csv（欄位：contact, type, result）
載入時依 contact + type 分組，同組多個 result 合併為選項陣列
聯動邏輯：
  第一層「接觸結果」(iv-contact) 變更 →
    篩選 contact 相同的資料，更新第二層選項
  第二層「訪談結果類型」(iv-type) 變更 →
    篩選 contact + type 相同的資料，更新第三層選項
  第三層「訪談結果」(iv-result) → 最終選定值
```

## 六、通知面板欄位（回應列內嵌）

回應列選擇「訊息通知」動作後，依通知方式（SMS／EMAIL／LINE／APP推播）展開對應欄位面板：

| 動作類型 | 欄位 | 說明 |
|----------|------|------|
| SMS | 業務性質代號、系統代號、簡訊內容 | 前二者為文字輸入（限10字元），簡訊內容為多行文字 |
| EMAIL | 專業類別代碼、信件主旨、郵件內文 | 「專業類別代碼」為畫面實際顯示文字 |
| LINE | 交易序號、推播樣版代號、通路代號、LINE訊息內文 | 「推播樣版代號」為畫面實際顯示文字 |
| APP推播 | 產品序號(appID)、訊息種類、來源序號、發送方式、訊息標題、訊息內文 | 產品序號限100字元，其餘限10字元 |

各面板下方均附有一行提示文字，說明需由外撥清單額外提供的核身資料變數（如 SMS 為手機號碼 `{:DAl}`）。

> 備註：此處欄位名稱為「回應設定」列內嵌通知面板（`notifyFields()`）所顯示的欄位，與玖、五「參數管理頁 - 訊息通知」頁籤所維護的欄位名稱（見該節）並不完全一致，屬程式碼中兩處獨立維護的通知欄位定義，此為現況如實記錄，非本文件刻意調整。

## 七、台詞搜尋選單

台詞下拉選單皆改為可搜尋的浮動面板（非原生 select）：
- 點擊台詞欄位 → 彈出浮動搜尋面板
- 輸入關鍵字 → 即時篩選（比對代碼或內容）
- 再聯絡的台詞欄位自動預篩「ZZA」開頭的台詞
- 點選項目 → 關閉面板，更新選擇值

## 三、檢核流程

```
1. 清除所有先前的錯誤標示（field-error class + error-msg span）
2. 依序檢核基本資訊欄位
3. 檢核問卷代碼（僅滿意度類）
4. 遍歷所有可見的回應設定列，逐欄檢核
5. 遍歷所有子動作列（threshold 類型的 before/after）
6. 若有任何錯誤 → 捲動至第一個錯誤欄位，中止儲存
7. 若無錯誤 → 呼叫 captureFormData() 序列化表單，儲存至 FLOW_LIST
```

## 四、儲存後行為

| 模式 | 行為 |
|------|------|

| 編輯 | 更新 FLOW_LIST 對應項目，回到列表頁，toast 提示「已更新 XXX」 |

| `data/flows/index.json` | 流程 manifest | 流程 ID 陣列 |
| `data/flows/{ID}.json` | 各流程完整資料 | 見「一、流程 JSON 結構」 |

## 三、資料載入優先序

```
1. 嘗試 fetch data/flows/index.json → 逐一載入各 JSON 流程檔
2. 若 JSON 載入成功 → 使用 JSON 流程資料
3. 若 JSON 載入失敗 → fallback 到 data/flows.csv + TEMPLATES 種子資料
4. CSV 參數檔（scripts/reasons/interview 等）獨立於流程資料載入，皆以 Promise.all 併行 fetch
5. 若 CSV fetch 失敗（如 file:// 協議） → fallback 到 JS inline 預設值
```

# 附錄 B：限制與已知條件

| 項目 | 說明 |
|------|------|
| 單一 HTML 檔 | 本系統為 Prototype 實作，前端邏輯全部內嵌於 `v2/index.html` |
| 資料持久化 | 目前為前端 in-memory + JSON 檔案，正式環境需對接後端 API |
| 台詞限制 | 每區塊限 1 句台詞（業務邏輯需求） |
| 流程編號不可修改 | 新增後唯讀，因與 IVR 活動代碼綁定 |
| 問卷代碼自動對應 | 不可手動輸入，完全依賴 `surveys.csv` 的 `flow_no` 欄位比對 |
| 關鍵字搜尋框 | 程式邏輯保留但畫面隱藏，暫未對外開放（見貳、三備註） |
| 「留電」動作 | 部分連動邏輯與種子資料仍保留，但 `data/actions.csv` 目前未提供此選項，下拉選單中不會出現（見柒、三備註） |
